# Runtimekontrakt – evidens och informationslager v2

## Proveniens

Explicit, derived, proposed och external ska hållas isär. Källor, härledning och osäkerhet ska vara spårbara på både objekt och relationer. Motstridiga källor får inte döljas genom att en källa väljs bort utan dokumenterad bedömning.

## Tre epistemiska lager

- `model/` = conceptual architecture.
- `market-reference/` = verifierbara påståenden om marknad/produkt.
- `actual-state/` = organisationsspecifika fakta.

Skyddsregler:

- conceptual need ≠ product choice,
- market capability ≠ actual use,
- actual use ≠ organizational offering,
- `can_realize` ≠ actual use.

Verifierad actual state kräver organisationsspecifik explicit eller härledd evidens. Extern leverantörs-/marknadsinformation kan beskriva vad en produkt kan göra men bevisar inte att organisationen använder den.

## Research

Extern research ska användas för att fylla identifierade evidensgap, inte för att tyst ersätta projektets källor. Modellförslag från research ska förbli `proposed`/`external` tills kriterierna för högre evidensstatus är uppfyllda. Osäkerhet, alternativa tolkningar och konflikter ska bevaras.
